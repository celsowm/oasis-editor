# Word-compatible Tab behavior

References: [WordCraft keyboard semantics](https://github.com/storytold/wordcraft/blob/main/crates/engine/src/cmd/text/enter_tab.rs), [ruler tabs](https://github.com/storytold/wordcraft/blob/main/crates/ui-egui/src/ruler_tabs.rs), [Microsoft Word keyboard shortcuts](https://support.microsoft.com/en-us/accessibility/word/keyboard-shortcuts-in-word), [table tabs](https://support.microsoft.com/en-us/word/set-tabs-in-a-table).

## Baseline and phases

1. Keyboard (initial change): literal tab through table-aware transactions; list demotion at start, not mid-item; no destructive replacement of whole paragraphs. Ctrl+Tab inside table when delivered; preserve browser shortcut elsewhere. Initial tests cover basic insertion, empty paragraph, list-start routing, full-selection safety, browser chord. Pending style inheritance, browser and full CI validation.
2. Paragraph/list semantics: introduce a context resolver distinguishing whole/multi-paragraph selections, partial selections, first/visual line start, list level and table context. Implement configurable Word-style AutoFormat first-line indent by document default interval, later-line/previously indented paragraph increment, Shift+Tab and Backspace reversals. Preserve relative individual paragraph indents and selected content; clamp list levels, verify zero-level behavior and inherited numbering.
3. Tables: distinguish adjacent vs boundary vs outside, resolve innermost table/story. Select target cell content, including all its paragraphs (Microsoft specifies forward and backward selection; WordCraft currently collapses backward). Append row at end and select first navigable cell in one undo transaction. Reuse existing row insertion but its current column target is not necessarily first cell. Test merged/nested tables, all stories, track changes, undo/redo. Ctrl+Tab may be browser-reserved; expose an accessible alternative.
4. Layout and ruler: compare current tabStops.ts to WordCraft, including explicit/default stops, right/center/decimal, bar stops (rule, not advancement), leaders, inherited clear, RTL, overflow, wrapping, caret and PDF. Ruler cycles stop kind, click adds, drag moves, drag off removes, double-click opens dialog; one undo per gesture; snap/Alt and collision with indent markers. Preserve existing working behavior.
5. Dialog and round trip: improve current TabStopsDialog with Word-style Set/Clear/Clear All, default interval, position validation, localization and shared components. Reuse paragraphTabs.ts for inherited clearing and document defaults. Verify DOCX w:tab, w:tabs, w:defaultTabStop; clipboard and PDF.
6. Focus/accessibility: intercept only editable document canvas, not site/popup/toolbar; ensure IME/read-only and keyboard escape from editor focus, all three shells. Browser/OS shortcuts may not reach JavaScript.

## Acceptance gates

Unit tests for routing, mutations, reversed/multi selection, list bounds, inherited styles, and one-step undo. Chromium/Firefox/WebKit browser tests for ordinary text, tables, ruler and dialog, focus and read-only, all shells. DOCX roundtrip and PDF/canvas geometry. Run TypeScript, native UI, Ribbon parity and icon guards, Vitest, production smoke and deployment; no weakened tests. Full parity remains unverified until these gates pass. Prefer Word behavior when it differs from WordCraft and record explicit differences.
