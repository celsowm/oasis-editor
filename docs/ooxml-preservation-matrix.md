## Changes in this slice

Header/footer story pairing now reads Transitional WML type and relationship
id by expanded name, and filters foreign elements sharing the same local name.
The section import path uses the same namespace identity. The active section
count no longer includes arbitrary foreign sectPr names. Strict WordprocessingML
is not certified by this change. The old DOM-only namespace sentinel is now a
production import/edit/export/reimport test covering noncanonical namespace
prefixes, a misleading ignored extension id/type on a reference, original
header/footer relationship IDs and paths, an ignored header-root extension,
and an unrelated custom XML part through three mutation cycles. The separate
preservation job executes that and existing source-backed regression tests.
New CI pending. The test does not yet exercise undo, deletion, object moves,
full MC semantics or SDK validation of this particular synthetic package.

Next: inspect results; add relationship-closure and opaque-object tests
before changing the model. Do not implement preservation by resurrecting an
explicitly deleted modeled object.

## Slice B — preservation-only opaque inventory and optional export guard

CI 44043529351 passed all five jobs, including the five basic and seven advanced positive DOCX specimens (zero SDK/OPC diagnostics), negative controls, and actual repeated source-backed namespace mutations. A finite clean corpus is not full interoperability.

The source snapshot now inventories opaque objects in Transitional main/header/footer/note/comment/glossary stories. This is an initial preservation representation, not a new editable run discriminant. It classifies unsupported DrawingML payloads (chart, diagram, ink, unknown drawing/group), w:object and non-image VML pict; if an AlternateContent contains an opaque object, the whole wrapper is retained in the inventory. Record standalone fragment XML, expanded-name structural signature, original owning part, ordinal, inline/anchor geometry, raw wrap information, relationship IDs and transitive internal target closure. Legacy office relid and arbitrary relationship prefix spellings are recognized. Cycles/shared targets are bounded by visited edges/parts; external links are recorded but never fetched. Source capture records warnings and unresolved-target diagnostics. No code in embedded payloads is executed.

Opt-in `exportEditorDocumentToDocxPreservingSource(doc, { requireOpaquePreservation: true })` (also Blob API) re-inspects the output and conservatively blocks changed/missing opaque fragments, changed/missing internal dependency data and closure differences, using OpaqueObjectPreservationError.diagnostics. It intentionally does not authorize deletion, copy, reparenting or relocation yet, and may reject equivalent lexical XML or namespace changes. This is a loss detector over the original and exported package, not a repair mechanism. Default behavior is unchanged. Unchanged source data is compared exactly as captured (XML text or base64); no claim of original encoding byte equivalence. Scanner errors block opt-in checks. Detection is limited to these story types and known Transitional containers; Strict, block-level foreign markup and full MC processing remain open.

Tests exercise closure, external links, cycles, missing/changed payloads, duplicate occurrences, MC fallback wrapper and an actual production import/edit/export with the strict outcome checked against the loss audit. The production test does not yet require successful retention of a chart after editing; blocking is explicitly an acceptable temporary result. Next: model real opaque inline objects, make successful mutation retention mandatory, add layout placeholder and safe delete/copy/undo. New CI pending.

## Slice D — explicit deletion and undo/redo

Release v0.0.358 passed npm publication, Pages, the full Vitest suite (363 passed files, 3 existing skips), and all five OOXML jobs. This slice adds a narrowly scoped keyboard Delete/Backspace path for a single opaque replacement character in the main document. A unique source signature, owner, and original ordinal authorize removal. The intent lives in immutable document state, not the shared source package, and participates in history snapshots. Export requires the authorized object to actually disappear and continues auditing every other unsupported object and its dependencies. Untracked, ambiguous or unauthorized losses, resurrected objects, invalid/stale intents, cross-story movement, and duplicated fragments remain guarded. Tracked deletion or non-main exact opaque deletion is a no-op for now. Bulk selection and cut are not newly authorized. All original OPC dependencies are conservatively retained (including unused embedded data); this is not secure erasure or garbage collection. A later graph-aware pruning phase must distinguish shared dependencies and intentional redaction. Tests require actual keyboard deletion, export/reimport, shared closure retention, undo and redo using the real history helpers. New CI pending.

## Slice G — transactional cross-story relocation

Release v0.0.361 passed all six workflows. The pure relationship planner is now shared by the model command and source-backed exporter. `relocateSelectedOpaqueObject(state, {zone, paragraphId, offset})` moves a selected inline opaque run between existing single-section default stories. It records an immutable relocation intent, rejects shared stories, tracked changes, anchored objects, notes, non-top-level paragraphs, existing anchors, more than one pending relocation and combined deletion. The export recomputes the plan from original source identity, overlays the rebuilt DOCX, appends the planned relationships to the actual destination part and audits the expected remapped object against its unchanged dependency closure and every unrelated object. Old relationships are retained deliberately. Destination drawing ID collisions fail closed. Tests require actual noncanonical header path, same ID in the two owners, preserved dependency bytes, successful reimport, undo/redo and rejected unauthorized movement. This is a core command, not a new drag/drop or clipboard UI binding. Multi-section, inherited/shared stories, multiple pending moves, anchored shapes, global drawing ID allocation and old-edge cleanup remain open. New CI pending.

## Slice I — authoritative source-backed export

The raw-fragment boolean escape hatch is removed from canonical export. Internal overlay/fingerprint rebuild derives an exact allowlist from a fresh OPC scan, plus the single recomputed relocation plan when present. The run serializer checks the exact raw XML, signature, object kind, replacement character and relationship IDs against that allowlist. The source-backed entry point recalculates inventory on a cloned snapshot, fails on inspection errors, and audits explicit deletion intents even if the cache is absent. Old documents without an inventory are not exempt from preservation. The baseline importer now passes the original captured OPC package explicitly. Tests cover missing/empty inventory, unchanged snapshot, unauthorized removal, attempted sibling injection and forged signature, alongside existing transfer/history tests. This is an additional provenance boundary, not a general XML sanitization/security certification; untrusted original packages and unrelated source XML mechanisms require their own security review. Cross-document clipboard transfer remains deliberately blocked until closure import and collision-safe identity allocation exist. CI pending.
